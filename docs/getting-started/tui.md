# TUI 使用说明

## 平台差异

| 平台 | 默认模式 | 打断方式 |
| --- | --- | --- |
| macOS | 带回声消除的全双工 | 直接说话 |
| Linux / Windows | 半双工 | 输入 `/interrupt` |

## 终端布局

TUI 采用全屏双区域布局。上方可滚动区域显示对话历史、实时语音转写、任务状态和连接日志。网关和麦克风状态以及常驻文本输入框固定在底部。异步输出和重连尝试不会中断文本编辑。使用 `PageUp` / `PageDown` 浏览历史记录，随时可按 `Ctrl-C` 退出。

## 文本和附件输入

除语音外，TUI 还支持文本、图片和普通文件输入：

- 直接在底部输入框中输入内容，按 Enter 发送。
- 粘贴本地文件路径，可立即将图片显示为 `[Image N]`，或将普通文件显示为 `@绝对路径`，为下一轮对话暂存该文件。
- 文本中的 `@文件路径` 将作为附件发送。
- 输入 `/mute` 可静音或恢复麦克风，输入 `/help` 可查看所有命令。

暂存的附件可随输入框文本或下一轮语音一起发送。从输入框中删除其锚点也会移除暂存的附件。

TUI 读取附件内容并将其发送至网关。实时语音前端仅接收元数据。当通过 `spawn_thinking` 委派时，网关将原始附件转换为 ACP ContentBlocks 供后端代理使用。`[Image 1]` 或 `@文件路径` 等文本锚点始终与其文件部分保持绑定，以支持多附件引用、重放和后端解析。每个附件大小限制为 8 MB，每轮附件总量限制为 12 MB。网关为每个附件分配一个稳定的会话内输入 ID。这样，后续的文本或语音轮次可以将之前提交的图片委派给后端，而无需将文件字节重新注入实时语音模型。

## macOS

macOS 始终使用 CoreAudio AEC 全双工模式：播放期间持续采集音频，支持直接语音打断，无需额外配置。CoreAudio 辅助程序默认编译至 `~/Library/Caches/qwaudio/tui/macos-voice-io`，并在首次启动时自动构建。

## Linux / Windows

默认使用随附的 Python 音频桥接程序（基于 `sounddevice` / PortAudio）以半双工模式运行：回复播放期间麦克风暂停。输入 `/interrupt` 可手动停止播放；播放结束或被中断后恢复采集。首次使用前，请安装 `sounddevice` 和系统 PortAudio。

您也可以启用不带回声消除的全双工模式：

```bash
qwenaudio tui --audio-mode full
```

该模式没有回声消除功能；请佩戴耳机，以避免扬声器音频导致的误识别或误打断。不同声卡和蓝牙耳机在不同采样率下对同时输入输出流的支持程度各异；如果持续遇到输入溢出、输出欠载或设备错误，请退出并回退到 `--audio-mode half`。

## 配置

默认音频模式也可以通过环境变量进行持久化设置：

```dotenv
QWEN_AUDIO_AGENT_TUI_AUDIO_MODE=half
```

将其设置为 `full` 等同于 `--audio-mode full`。完整参数详情请参阅[配置](../configuration.md)。
