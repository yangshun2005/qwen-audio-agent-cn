# 工作与权限

配置好[后端代理](../backends/overview.md)后，可让助手检查计算机信息、编辑文件、编写软件，或使用后端的工具和技能。执行能力、身份验证以及可访问的资源均取决于该后端环境。

若未配置后端，前端不会暴露 `spawn_thinking`，也不支持定时后端执行。聊天、可用的前端工具以及定时提醒功能仍然可用。状态和取消工具仍可用于管理提醒及其他现有记录。

## 开始与继续

- 开始工作：“制作一个极简网页游戏。”
- 添加指令：“给那个页面设置深色背景。”
- 检查进度：“进行到哪一步了？”
- 取消：“取消那个游戏。”

工作以异步方式运行，因此你可以继续聊天。请指明你所指的工作，或使用其卡片标识符，尤其是在多个任务同时处于活动状态时。原生会话恢复、独立工作以及各个工具均依赖于后端；某一后端的能力并不代表所有后端都具备。

## 理解工作状态

“已接受”仅表示请求已被接收，而非已完成。卡片可能显示排队中、运行中、等待输入或授权、准备发布公告以及最终结果。查询和取消操作也必须根据其实际返回的状态来判断；请求取消并不代表操作已停止。

后端可能会提出后续问题，而非直接返回最终交付物。回答该问题以继续。如果工作失败，请保留错误信息，并检查后端身份验证、模型配额及工具配置。仅连接语音前端并不能证明后端可用。

## 允许或拒绝

当后端发出真实的权限请求时，界面会显示该操作，前端可征求你的决定。请自然表达你的意见：

| 决定 | 效果 |
| --- | --- |
| 允许任务 | 允许该任务及其后续操作，直至完成、失败或取消；其他任务需单独批准。 |
| 始终允许 | 允许当前前端会话中后续由 Gateway 管理的权限请求，并非对所有后端进行永久更改。 |
| 拒绝 | 拒绝当前请求。 |

普通同意即表示“允许任务”，包括该任务中的后续写入或删除操作。授权仅在当前 Gateway 进程中有效；重启后需重新批准。

如果多个工作项正在等待授权，请指明你所指的那一项。并非所有后端都会暴露权限事件。对于不支持审批的后端，前端无法为其创建沙箱。“始终允许”也不一定能覆盖后端原生的安全限制。

有关 `native` / `full` 启动模式及后端差异，请参阅
[后端权限模式](../configuration/backend.md#backend-permission-modes)。

前端 MCP / OpenAPI 服务拥有各自的确认和身份验证机制。后端审批并非适用于所有工具的通用安全层。请仅启用你信任且需要的操作。
