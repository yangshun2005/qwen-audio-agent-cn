# 实时语音聊天机器人运行时路线图

> 状态：提案
>
> GitHub 追踪：[#185](https://github.com/QwenAudio/qwen-audio-agent/issues/185)
>
> 范围：在保留一个活动后端代理的同时，将 qwen-audio-agent 重构为一个边界清晰、可扩展、面向标准的实时语音聊天机器人运行时，通过异步工作桥连接到用户自己的操作代理。

## 1. 产品定义

qwen-audio-agent 包含两个解耦的运行时，对用户而言表现为一个助手：

1. **实时语音聊天机器人** 负责对话。它处理语音、文本、图像、附件、上下文、记忆、搜索、知识/RAG、有界低延迟工具和呈现。
2. **后端操作代理** 访问文件、代码、应用程序、设备和外部系统。它使用自己的模型、配置、工具、MCP 服务器、技能和会话执行长时间运行、多步骤或特权工作。

`spawn_thinking` 是它们之间唯一对模型可见的工作交接。它发送用户目标和输入引用；前端从不选择后端会话、执行模式、委派策略、工具或子代理。

只有一个用户选择的后端处于活动状态。多后端路由不在本路线图范围内。

## 2. 架构不变量

1. 未配置后端时，前端聊天、记忆、搜索和可选注入的知识提供者继续工作。
2. 后端排队、执行、授权和故障永远不会阻塞实时对话。
3. `spawn_thinking` 仅等待接收，从不等待完成。
4. 前端自然且恰好一次地呈现每个后端结果。
5. 前端运行时从不依赖 ACP 或后端产品。
6. 工作运行时不包含会话、协调器-MCP 或后端拓扑知识。
7. 后端适配器发出标准工作事件和构建产物；它们从不直接发送客户端事件。
8. 实时提供者从不调用后端或选择工作策略。
9. 客户端消费公共协议，从不推断内部状态机。
10. 知识提供者拥有其索引生命周期；前端记忆提取仍然是系统任务，而不是用户后端工作。

## 3. 目标边界

```text
桌面 / WebUI / TUI
          │ AG-UI 兼容事件 + qwen.audio 扩展
          ▼
网关传输
          ▼
前端聊天机器人运行时
├── 实时会话 / 对话上下文
├── 前端工具运行时
├── 搜索 / 知识
├── 记忆 / 笔记 / 提醒
└── 呈现运行时
          │ WorkSubmissionPort
          ▼
工作运行时
├── 状态 / 队列 / 授权
├── 构建产物 / 通知 / 恢复
└── 调度器
          │ BackendPort
          ▼
单一后端运行时
          ▼
ACP / 未来 A2A / 自定义后端适配器
```

依赖方向是固定的：

```text
传输 → 应用 → 领域 ← 适配器
```

## 4. 核心契约

### RealtimeProviderPort

提供者暴露 `connect`、`updateSession`、`sendAudio`、`sendInput`、`sendToolResult`、`createResponse`、`cancelResponse`、`close`、`capabilities` 和 `subscribe`。DashScope、OpenAI 兼容、语音到语音和私有提供者实现此端口。

### FrontendTool

每个工具声明其名称、描述、输入/输出 Schema、执行器和一个策略：

```text
readOnly / requiresApproval
timeoutMs / maxResultBytes / maxCallsPerTurn
```

工具可以在轮次内返回结果、返回异步接收回执，或对现有工作进行操作。它们的执行器实现这些行为，无需执行模式标签；策略仅包含有效的运行时约束。核心与可选提示边界存在于文档和测试中，而非运行时工具协议中。

### Work

任务记录在接收、查询、取消、事件和结果交付中使用一个简短的 `task_id`。它们携带所有者、对话、轮次、目标、多模态输入、状态、活动、授权、构建产物和时间戳。公共状态与 A2A 任务语义一致：`submitted`、`working`、`input_required`、`auth_required`、`completed`、`failed` 和 `cancelled`。网关特定阶段保持内部状态。后端提交添加一个规范的自然语言 `instruction`；前端记忆、聊天历史、路由字段和序列化的 Work 记录从不作为模型可见的后端输入。

### BackendPort

后端实现 `describe`、`start`、`health`、`submit`、`status`、`cancel`、`respondAuthorization`、`respondInput`、`subscribe` 和 `close`。ACP 会话、协调器提示、协调器 MCP 和原生委派保持在 ACP 适配器内部。每个适配器实现完整的方法表面，并在组合边界进行检查。可选能力由 `describe()` 声明并显式拒绝，从不从缺失函数推断。`submit`、`status`、`cancel`、`respondAuthorization` 和 `respondInput` 操作一个网关 `taskId`；后端私有会话和任务标识符从不跨越端口。适配器将相同的规范指令和原生附件部分投影到 ACP、A2A 或自定义传输中，同时保持关联元数据私有。AgentClient 恰好拥有一个注入的后端实例。驱动选择、配置文件构建和协议特定依赖属于适配器工厂，而非运行时门面。

### Artifact 和呈现

Artifacts 使用与 A2A 对齐的 `artifactId`、`name`、`description` 和 Parts 形状。每个 Part 恰好包含文本、URL、base64 原始内容或结构化数据之一，以及其 MIME 类型。授权是一个有界 Work 请求，包含身份、状态、摘要、类别和时间戳；它携带决策请求，从不携带凭据。呈现包含面向前端的事实材料和交付策略，而不是必须逐字朗读的脚本。后端问题仍然是同一活动 Task 的一部分：适配器发出有界输入请求并通过 `respondInput` 恢复；因此，单独解析的后端调用不被解释为 Task 完成。

重启恢复是一个显式 Work 策略：安全提醒被重新调度，可恢复的委派运行被重新附加，中断的执行失败一次，持久化的取消意图保持取消状态。结果交付使用持久化的索赔租约；确认在其事件发布之前被检查点化，只有未确认或过期的租约才能被重放。

## 5. 标准策略

| 边界 | 策略 |
| --- | --- |
| 客户端 ↔ 网关 | 逐步投影稳定的 AG-UI 事件；对音频、播放、所有权和休眠使用 `qwen.*` 扩展 |
| 网关 ↔ 实时模型 | OpenAI Realtime 兼容提供者端口 |
| 模型工具 | Function Calling + JSON Schema |
| 外部工具和数据 | MCP；用于 REST 服务的 OpenAPI 适配器 |
| 网关 ↔ 后端代理 | 带有内置 ACP 和 A2A 适配器以及自定义协议的 BackendPort |
| 多模态内容 | MIME 类型加文本、URI、二进制或结构化数据 Parts |
| 可观测性 | 结构化日志和渐进式 OpenTelemetry 对齐追踪 |

外部协议通过投影器和适配器进入；它们不会成为内部领域模型。

## 6. 前端能力边界

前端可以运行由总延迟、调用次数、结果大小和中断策略约束的有界短工具循环。它拥有多模态对话、历史、偏好、记忆、笔记、提醒、网络搜索、URL 获取、引用、完整上下文、知识/RAG、工作控制、授权中继和自然结果呈现。

文件系统和 Shell 访问、代码项目、应用程序/设备/浏览器控制、长时间运行或特权工作、子代理、会话、计划、委派策略以及后端 MCP/技能/模型保持后端私有。

## 8. 目标仓库结构

```text
server/src/
├── app/                  # 组合根
├── transport/            # HTTP / WebSocket / AG-UI 投影器
├── frontend/             # 聊天机器人运行时
├── work/                 # 用户工作领域
├── backend/              # 后端端口/运行时/适配器
├── providers/realtime/   # 实时提供者适配器
└── platform/             # 配置/身份/持久化/日志/安全

shared/                   # 迁移期协议和客户端运行时
packages/                 # 契约稳定后的协议/客户端/后端 SDK
```

目录仅随责任提取和测试移动；路线图不授权表面性的批量重命名。

## 9. 强制依赖规则

```text
frontend/        不得导入 backend/adapters/
work/            不得导入 ACP、会话或后端产品
transport/       不得实现领域状态机
providers/       不得调用 BackendPort
backend/adapters 不得直接发出客户端事件
clients          不得推断内部网关状态
shared/protocol  不得依赖服务器
```

## 10. 质量门禁

每个阶段运行 lint、完整测试套件、发布检查、公共协议兼容性测试、无后端聊天测试、非阻塞后台工作测试、中断测试、恰好一次呈现测试以及适配器/提供者一致性测试套件。

重构 PR 默认不更改用户行为。行为更改需要自己的提交、双语文档和端到端测试。

## 11. 非目标

- 多个并发活动或自动路由的后端代理。
- 将前端转变为编码代理或通用长时间运行代理。
- 迁移到 Open WebUI、LiveKit 或其他完整平台。
- 立即替换现有网关协议。
- 发明新的 MCP、A2A 或技能协议。
- 为统一性暴露后端会话或私有任务拓扑。
