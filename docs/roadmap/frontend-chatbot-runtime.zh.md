# 实时语音聊天机器人运行时路线图

> 状态：提案
>
> GitHub 跟踪：[#185](https://github.com/QwenAudio/qwen-audio-agent/issues/185)
>
> 范围：在保持单一后台 Agent 的前提下，将 qwen-audio-agent 重构为边界清晰、
> 可扩展、相对标准化的实时语音聊天机器人运行时，并通过异步工作桥接入
> 用户自己的办事 Agent。

## 1. 产品定义

qwen-audio-agent 由两个彼此解耦、对用户表现为一个助手的运行时组成：

1. **实时语音聊天机器人** 始终拥有用户对话。它负责语音、文本、图片、附件、
   对话上下文、记忆、搜索、知识/RAG、低延迟前台工具和结果表达。
2. **后台操作 Agent** 负责访问文件、代码、应用、设备和外部系统，执行长耗时、
   多步骤或需要权限的工作。它使用自己的模型、配置、工具、MCP、技能和会话。

`spawn_thinking` 是二者之间唯一的模型可见工作交接入口。它只提交用户目标和输入引用，
不允许前台选择后台会话、执行方式、委托策略、工具或子 Agent。

当前版本只激活一个用户选择的后台。多后台路由不属于本路线图。

## 2. 架构不变量

以下规则由文档、依赖检查和测试共同保证：

1. 没有后台 Agent 时，前台仍能完成正常聊天、记忆、搜索，以及通过可选 Provider
   注入的知识检索。
2. 后台排队、运行、等待权限或失败，不阻塞前台继续对话。
3. `spawn_thinking` 只等待受理回执，不等待后台工作完成。
4. 后台结果由前台在安全的语音窗口自然表达，且只交付一次。
5. 前端运行时不依赖 ACP、OpenCode、OpenClaw 或任何具体后台实现。
6. 工作运行时不含会话、MCP 协调工具或后台拓扑知识。
7. 后台适配器不直接向客户端发送事件，只产生标准工作事件和构建产物。
8. 实时 Provider 不调用后台，不解释工作执行策略。
9. 客户端只消费公开协议，不自行推导网关内部状态机。
10. 知识 Provider 管理自己的索引生命周期；前台记忆提取仍是系统任务，而不是用户
    后台工作。

## 3. 目标边界

```text
桌面 / WebUI / TUI
          │ AG-UI 兼容事件 + qwen.audio 扩展
          ▼
网关传输层
          ▼
前端聊天机器人运行时
├── 实时会话 / 对话上下文
├── 前端工具运行时
├── 搜索 / 知识
├── 记忆 / 笔记 / 提醒
└── 表达运行时
          │ 工作提交端口
          ▼
工作运行时
├── 状态 / 队列 / 授权
├── 构建产物 / 通知 / 恢复
└── 调度器
          │ 后端端口
          ▼
单一后台运行时
          ▼
ACP / 未来 A2A / 自定义后台适配器
```

依赖方向固定为：

```text
传输层 → 应用层 → 领域层 ← 适配器
```

## 4. 核心契约

### 4.1 实时 Provider 端口

实时 Provider 只负责将供应商协议投射成统一的实时会话事件：

```js
{
  connect,
  updateSession,
  sendAudio,
  sendInput,
  sendToolResult,
  createResponse,
  cancelResponse,
  close,
  capabilities,
  subscribe,
}
```

DashScope、OpenAI 兼容、语音到语音和私有 Provider 都实现该端口。

### 4.2 前端工具

```js
{
  name,
  description,
  inputSchema,
  outputSchema,
  policy: {
    readOnly,
    requiresApproval,
    timeoutMs,
    maxResultBytes,
    maxCallsPerTurn,
  },
  execute,
}
```

工具可以在当前轮次返回结果、返回异步受理回执，或操作已有工作。
这些行为由具体执行实现决定，不另设执行模式标签；策略只承载实际参与运行的约束。
核心与可选能力的提示词边界通过文档和测试维护，不加入工具运行时协议。

### 4.3 工作

任务是网关管理的异步工作单元，不镜像后台内部任务图。它只使用一个短
`task_id` 贯穿受理、查询、取消、事件和结果交付，并包含所有者、对话、轮次、
目标、多模态输入、状态、活动、权限、构建产物、表达和时间戳。

公共状态向 A2A 任务语义靠拢：

```text
submitted → working → completed
                  ├→ input_required
                  ├→ auth_required
                  ├→ failed
                  └→ cancelled
```

`queued`、`delegated`、`finalizing` 和 `cancelling` 等仅作为网关内部阶段，
不得成为后台适配器的前置假设。

### 4.4 后端端口

```js
{
  describe,
  start,
  health,
  submit,
  status,
  cancel,
  respondAuthorization,
  respondInput,
  subscribe,
  close,
}
```

ACP 会话、协调提示词、协调 MCP 和原生委托全部属于 ACP 适配器内部。
每个适配器必须实现完整方法面，并在组合边界接受校验。可选能力由 `describe()` 声明，
不支持时必须明确拒绝，不能依赖“缺少某个函数”来推断。`submit`、`status`、`cancel` 与
`respondAuthorization`、`respondInput` 只操作网关 `taskId`，后台私有会话与远程任务 ID 不越过端口。
后台追问不会结束当前任务：适配器发出有界输入请求，网关经 `respondInput`
把用户回答交回同一任务后继续执行。因此一次后台调用返回不再等同于任务已完成。
AgentClient 只持有一个注入的后台实例。驱动选择、配置文件构造和协议专属依赖属于
适配器工厂，不再由运行时门面承担。

### 4.5 构建产物与表达

构建产物采用与 A2A 对齐的 `artifactId`、名称、描述和部件结构。每个部件只包含
文本、URL、base64 原始内容或结构化数据中的一种，并声明 MIME 类型。授权
是有界的工作决策请求，包含身份、状态、摘要、类别和时间戳，只转交决策，不承载凭据。
表达只携带供前台表达的事实材料和投递策略，不携带必须逐字播报的脚本。

重启恢复是明确的工作策略：安全的提醒重新调度，可恢复的委托重新挂接，中断的执行只
失败一次，已经持久化的取消意图仍保持取消。结果投递采用持久化领取租约；确认送达先落盘
再发布事件，只有未确认或租约过期的结果才允许重新投递。

## 5. 标准协议策略

| 边界 | 策略 |
| --- | --- |
| 客户端 ↔ 网关 | 逐步兼容 AG-UI 稳定事件；音频、播放、所有权和休眠使用 `qwen.*` 扩展 |
| 网关 ↔ 实时模型 | OpenAI 实时兼容 Provider 端口 |
| 模型工具 | 函数调用 + JSON Schema |
| 外部工具与数据 | MCP；普通 REST 服务可通过 OpenAPI 适配器 |
| 网关 ↔ 后台 Agent | 后端端口；内置 ACP 与 A2A 适配器，也可接自定义协议 |
| 多模态内容 | MIME 类型 + 文本 / URI / 二进制 / 结构化数据部件 |
| 可观测性 | 结构化日志；逐步接入 OpenTelemetry 追踪语义 |

标准协议通过边界投影器或适配器接入，不直接成为内部领域模型，避免协议升级
扩散到核心业务。

## 6. 前台能力边界

前台允许有界的短工具循环：总耗时、调用次数、结果大小均受工具策略限制，用户
插话时可立即终止当前前台循环。前台负责：

- 连续语音、文本和多模态对话；
- 对话历史、用户偏好、长期记忆、笔记和提醒；
- 网页搜索、URL 获取、引用；
- 完整上下文与知识/RAG；
- 后台工作查询、取消和权限转述；
- 后台最终结果的自然表达。

后台私有能力包括：

- 文件系统、Shell、代码工程和应用操作；
- 手机、浏览器、桌面和硬件控制；
- 长时间、多步骤或高风险工作；
- 子 Agent、会话、执行计划和委托策略；
- 后台自己的 MCP、技能、模型和工具。

## 8. 仓库目标结构

```text
server/src/
├── app/                  # 组合根
├── transport/            # HTTP / WebSocket / AG-UI 投影器
├── frontend/             # 聊天机器人运行时
├── work/                 # 用户工作领域
├── backend/              # 后端端口/运行时/适配器
├── providers/realtime/   # 实时 Provider 适配器
└── platform/             # 配置/身份/持久化/日志/安全

shared/                   # 迁移期公共协议与客户端运行时
packages/                 # 接口稳定后再拆 protocol/client/backend-sdk workspace
```

不进行一次性目录搬迁。每次移动必须伴随职责提取和测试。

## 9. 强制依赖规则

```text
frontend/        不得导入 backend/adapters/
work/            不得导入 ACP、会话或具体后台
transport/       不得实现业务状态机
providers/       不得调用后端端口
backend/adapters 不得直接向客户端发事件
clients          不得自行推导网关内部状态
shared/protocol  不得依赖 server
```

## 10. 质量门禁

- `npm run lint`
- `npm test`
- `npm run release:check`
- 公共协议兼容测试
- 无后台聊天测试
- 后台工作不阻塞对话测试
- 打断不取消已提交工作测试
- 最终结果恰好一次播报测试
- 适配器和 Provider 一致性测试

重构 PR 默认不改变用户行为。行为变化必须独立提交、更新中英文文档并增加端到端测试。

## 11. 非目标

- 同时连接或自动路由多个后台 Agent；
- 将前台建设成编程 Agent 或通用长任务 Agent；
- 迁移到 Open WebUI、LiveKit 或其他完整平台；
- 立即替换现有网关协议；
- 自创新的 MCP、A2A 或技能协议；
- 为了统一而暴露后台会话和内部任务拓扑。
