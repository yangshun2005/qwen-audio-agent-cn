# 架构概述

qwen-audio-agent 是一个实时语音运行时，让 AI 智能体保持对话、工作和在场状态。它被组织为三层架构，层与层之间恰好有两个协议面。

![三层架构](../qwen-audio-agent-three-layer-architecture-en.png)

## 三层架构

1. **客户端 — 环境层。** TUI、WebUI、桌面球体，或您自己的客户端。客户端负责 I/O 和展示，发布环境状态（窗口焦点、在场状态、休眠/唤醒），并传递用户信号。用户如何唤醒助手（唤醒词、热键、点击）完全是客户端的事。客户端不持有记忆；它们只转发信号。

2. **网关 — 对话层和状态平面。** 两个部分共享一个进程：
   - **实时前端** 是一个轻量级语音智能体：全双工语音、即时回答，以及刻意精简的一组对话工具，包括搜索、记忆、提醒和工作控制。
   - **网关控制平面** 是确定性的——路由路径中不涉及额外的 LLM。它负责任务台账、权限仲裁、公告策略，以及前端和后端之间的注入防御。

3. **后端 — 执行层。** `BackendPort` 之后的任何内容：一个 ACP 智能体（OpenCode、OpenClaw、Qoder、Qwen Code、MiniMax Code、Kimi Code、Claude Code、Codex、DeepSeek、Pi，或您自己的）、一个远程 A2A 智能体，或使用后端适配器 SDK 构建的自定义适配器。ACP 集成会保持一个持久的协调会话以支持持续工作；后端的内部工具、技能和子会话是后端私有的，永远不会成为新的层。

## 两个协议面，仅此而已

- **客户端 ↔ 网关** — [网关契约](../contract.md) 和 [客户端协议](../gateway-protocol.md)：通过单个 WebSocket 传输的类型化事件。
- **网关 ↔ 后端** — `BackendPort`。协议细节保留在 ACP、A2A 或自定义适配器内部；启动和能力行为由注册的驱动程序管理。参见 [支持的后端](../backends/overview.md) 和 [后端适配器 SDK](../reference/backend-adapter-sdk.md)。

将运行时适配到新场景意味着更换客户端（环境）和后端（该环境的工具）。网关仅通过声明式接缝进行更改：角色文件、公告策略、前端 MCP 工具和 OpenAPI 操作，以及知识/记忆提供者。参见 [场景示例](../scenarios/smart-cockpit.md)。

## 非阻塞循环

当请求需要实际工作时，前端调用 `spawn_thinking`，对话立即继续——工作在后台会话中作为异步任务运行，其结果在安全的插入点流回同一对话。语音路径中的任何内容都不会等待后端。
